# DEC-0001 — Personal Adoption of the Professional Module Order

## Problem and context
A new personal Agent SDLC project needs a rational workflow without confusing course presentation with software delivery. The authoritative documentary sources are the full [original report](../../../raw/agent-sdlc-13-modulos/chat-1/turns/0002-assistant-original.md) §§1,7–10 and the [initial request](../../../raw/agent-sdlc-13-modulos/chat-1/turns/0001-user-original.md) §2. The decision is **explicit in the report** and is not an approval from the course author.

## Alternatives
- Preserve the academic sequence `M1 → M2 → … → M13`: appropriate for learning, but not necessarily the best prioritization for starting a real product.
- Start with **M2 (SDD)**: reasonable when the business problem and behaviors are well understood; risky if specifications are premature.
- Start with **M4 (planning)**: reasonable with clear business objectives; risky if unvalidated work is planned.
- Start with **M1**, then follow a work-oriented sequence: **chosen personal alternative**. The comparison and limits remain in the Spanish report §7.

## Adopted decision
**Status:** `confirmed` **for personal use only**, as stated in the report's adoption record dated **2026-10-20 (time not recorded)**. Sequence: **M1 → M3 → M6 → M4 → M2 → M5 → M13 → M7 → M8 → M9 → M10 → M11 → M12**. Use Claude Code as an engineering assistant from the beginning (M1, then practical setup in M3). Develop the actual business agent mainly around M9 only when requirements, tool permissions, and verification strategy are adequate. M13/security spans the lifecycle. **The published CursoIA curriculum is not reordered.**

## Owner confirmation for this English edition
In the current October 20, 2026 follow-up, **Diego Aguirre** identified himself as owner of this research and explicitly authorized required approvals and confirmations to recreate the identical documentary package in English, preserving Spanish raw originals. ## Consequences and boundaries
Treat the order as a prioritized guide, **not** a rigid waterfall. SDD structures specifications but does not replace QA, agent evaluations, deployment, security, or operations. No actual stack, business architecture, product implementation, production readiness, cybersecurity outcome, external permission, or unperformed task is approved or claimed by this decision.
