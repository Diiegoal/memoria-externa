# Retention Policy

## Metadata and approval
Local version 1.0, English edition. Diego Aguirre has approved **use of this policy guidance for the personal package** but has not specified a numerical retention period or an external deletion schedule. Those fields remain **PENDING_DEFINITION**, not fictitiously set. Differential protection is recommended.

## Retention matrix
| Category | Proposed rule | Status |
|---|---|---|
| raw originals | Retain while evidence traceability is needed, subject to owner consent, privacy and secure storage | Duration not specified |
| decisions and events | Retain the history required for personal audit and correction, with minimal access | Duration not specified |
| current state, handoff and indexes | Rebuildable from authoritative records | Review as needed |
| temporary generated context | Delete after authorized use, where practical | No automatic deletion configured |

## Exceptions
Statutory obligations, legitimate deletion requests, sensitive material, or third-party copyright require a real contextual assessment; do not assume a legal obligation solely from this document.

## Controlled deletion procedure
Obtain the owner's scoped authorization; inventory actual copies; inspect references and public history; revoke affected credentials if necessary; delete controlled copies; record a real audit event. Git history requires separate remediation if it already contains secrets. An approval to generate this ZIP is not advance authorization to delete original records.

## Audit status
**Demonstrated deletion requests:** none. **Deletion performed:** NOT_PERFORMED. When a real deletion occurs, capture the consent, date, scope, method, and results.
